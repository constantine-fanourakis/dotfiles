# Commit message

We use [Conventional Commits](https://www.conventionalcommits.org/). Format:
`type(scope): subject`.

**Allowed types:** `feat`, `fix`, `refactor`, `docs`, `test`, `chore`, `perf`, `style`, `build`, `ci`.

**Scope** is the affected package or area (e.g. `auth`, `web`, `mobile`, `ui`).

**Subject:** imperative mood, lowercase, no trailing period, ≤72 chars.

## Steps

1. Run `git status` and `git diff --staged` (fall back to `git diff` if nothing is staged).
2. Pick the single best `type` and `scope` for the change.
3. Write the subject line; if the change is non-obvious, add a body separated by a blank line.
4. Show me the message and ask before committing.

## Examples

- `feat(auth): add passkey enrollment flow`
- `fix(mobile): prevent crash when keyboard opens on iOS 17`
- `refactor(ui): extract Button variants into a discriminated union`
- `docs(readme): document pnpm setup for first-time contributors`

Never include co-author trailers or "generated by" tags unless I ask.
